# Unresolved High-Impact Questions

These are intentionally not solved in the seed. Resolve them one at a time when they become consequential.

1. Should Obsidian be canonical storage, a generated view, a private workspace, a shared workspace, or a mixed surface with explicit boundaries?
2. What is the exact task identity and checkpoint schema once real multi-session tasks begin?
3. Which provider adapters are needed first, and what capability contract should they share?
4. Which generated cognition structures are worth storing, and which should always be rebuilt on demand?
5. How should successful repository-specific improvements be evaluated and promoted into the common seed?
6. What exact JSON task-state schema is needed after graph or harness automation proves a machine-readable companion useful?
